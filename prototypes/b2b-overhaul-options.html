B2B Stage Overhaul

Every deal screen rebuilt from the same parts, in the same order, with the same buttons in the same place. Pick a layout below and step through all eight stages with the same sample deal.

What's inconsistent today

  • 5line tables. Pricing, approval, quote, listing and the read-only view each draw the lines differently, with different columns.
  • 2totals widgets. A profit strip on some stages, nine stat tiles on others. The full quote sheet shows both.
  • ≠Buttons move. Close vs Cancel, Decline before or after Close. Pickup and pricing have two primary buttons and approval has none.
  • ?No sense of where you are. A deal screen never shows the stage among the eight.
  • 6heading styles, 27 font sizes, ~20 corner radii, 527 B2B CSS classes.
  • ¶Help paragraphs on nearly every stage.

The rules every option follows

  • 1One header. Ref, client, stage chip. Delete and Decline sit in a ⋯ menu; × closes.
  • 2Stage rail. All eight steps, current one marked.
  • 3Status line. Who it's waiting on and for how long.
  • 4Same facts, same order on every stage.
  • 5One numbers strip: Units, Offer, Resale, Gross, Net.
  • 6One line table. Each stage picks its columns.
  • 7One section style for Files, Notes, Client Quote and History.
  • 8One primary button, always in the same spot. If it's disabled, the reason sits beside it.
  • 9Labels, not paragraphs. Anything longer becomes a tooltip or goes.

How it gets built

  1. Foundation

    Tokens, one type scale, and the shared pieces: header, rail, status, facts, numbers, line table, section, footer. Nothing changes on screen yet.

  2. Port the stages

    One at a time, deleting each old renderer as its replacement lands. Simplest first: Completed, Listing Store, Pricing Store, Pickup, Approval + Quote, Listing. Pricing last.

  3. Copy pass

    Every help paragraph cut to a label or a tooltip. Error messages stay plain and specific.

  4. List views

    Needs You, Pipeline, Completed, Evaluations, Clients: same chips, cards, tiles and empty states as the deal screen.

  5. Phones

    One narrow-screen pass across every stage, built into the shared pieces, not per stage.

  6. CSS cleanup

    Delete the dead Overview styles and every class the old renderers leave behind.

No database or edge-function changes. Each phase is checked with the B2B browser suites at phone, tablet and desktop widths.

Decided

  1. Layout: the deal workspace (B).
  2. Pipeline is the main view. The Needs You tab goes; the board’s “Needs you only” switch replaces it.
  3. Closing: the × in the header (and Esc). No Close or Cancel buttons in the actions.
  4. ⋯ menu holds Request Deletion and Decline Deal.
  5. Evaluations open in the same workspace with no stage rail. Corp only.
